# 雪板交付封存台（hxyfront-62004）

面向滑雪板调校店交付环节的封存管理前端。技师在维护工单完成后安排雪板进入封存位，等待客户到场取板。

## 业务规则

1. **封存准入**：工单只有「底板损伤全部修补完成」且「刃角复核通过」才能进入封存位，封存时登记取板联系人与到场日，系统分配封存位和 6 位封存码。
2. **整单拒绝**：封存位不足，或同客户已有「已封存/催取中」的未取板工单时，整单拒绝，原工单状态与封存位占用均不变。
3. **封存后退回**：封存/催取期间新增损伤或改动刃角（侧刃/底刃），工单立即退回修补、释放封存位，刃角需重新复核。
4. **取板核对**：取板必须输入与封存码一致的 6 位码，核对通过才交付并释放封存位；不一致仅留痕、拒绝取板。
5. **超期催取**：超过登记到场日仍未取板的封存单自动转催取，保留封存位与全部流转记录，仍可凭码取板。
6. **联动与持久化**：筛选、封存位看板、客户历史与工单状态实时同步；数据只存浏览器 localStorage，刷新/重开保留。

## 代码结构（规则 / 状态 / 界面三分离）

- `src/rules.ts` —— 业务规则层（纯函数）：封存准入评估、拒绝条件、退回判定、封存码核对、超期催取、筛选、客户历史、封存位推导。
- `src/state.ts` —— 状态层：`useShop` 统一管理工单、封存位、筛选，localStorage 持久化与跨天催取扫描。
- `src/App.tsx` —— 界面层：工单卡片、修补/刃角操作、封存登记、取板核对、筛选与封存位看板、客户历史。
- `src/types.ts` —— 领域类型定义。
